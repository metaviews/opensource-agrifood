# farmOS

- Status: `curated`

## Problem addressed

farmOS provides farm management, planning, record keeping, and agricultural data collection in a web-based system that farms can host and extend.

## Open layer

Open-source software, data structures, community modules, and self-hostable farm infrastructure.

## What is actually open

The farmOS codebase is publicly available and the principal repository identifies a GPL-2.0 licence. farmOS can be self-hosted, modified, and extended. Subscription hosting is available separately through Farmier, whose subscriptions support continued development.

## Governance and control

The open code and self-hosting model give farms and implementers technical control over deployment. Practical control depends on hosting capacity, module choices, service providers, and the data practices of each deployment.

## Evidence of use

The project has a long public development history and reported a 4.0.4 release on 2026-07-16. Repository activity demonstrates maintained software; it does not by itself establish broad farmer adoption or impact.

## Maintenance and funding

farmOS combines community development, donations, contribution pathways, and subscription hosting. This makes it a useful case for examining how open agricultural software funds maintenance without closing the core codebase.

## Why it belongs

farmOS adds the operational farm-management layer missing from the initial collection. It can be compared with ODK’s field-data collection and OADA’s interoperability ambitions while focusing on day-to-day farm records and planning.

## What it does not demonstrate

Open and self-hostable software does not guarantee farmer control, data portability in practice, responsible data governance, or successful deployment in low-resource contexts.
